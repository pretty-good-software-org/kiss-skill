# template-agent-skill

`template-agent-skill` is the canonical organization template for repositories that publish one standalone Agent Skill
as a Claude plugin. It combines the `template-python` toolchain with Agent Skills metadata validation, initialization
through `orgctl`, focused tests, and CI.

## Installation

```bash
orgctl repo create <repo-name> \
  --template template-agent-skill \
  --profile ci_lint \
  --description "<one-line description>" \
  --auto-merge \
  --clone-dir "$HOME/Projects/<repo-name>"
```

`orgctl` creates the repository through the organization OpenTofu registry, waits for infrastructure checks, applies the
change, clones the repository, and runs `orgctl repo init`. Initialization replaces identity strings, deletes
`template.init.toml`, and stages the renamed nested-skill result for review.

Local development requires [mise](https://mise.jdx.dev/) and an authenticated
[GitHub CLI](https://cli.github.com/) session for organization repository initialization.

## Usage

Before the first commit:

1. Replace the template skill instructions with the target behavior.
2. Give `SKILL.md` and `apm.yml` one identical, specific description, then run `apm pack --force` to regenerate
   `.claude-plugin/plugin.json` from `apm.yml`.
3. Remove resources and scripts the target skill does not use.
4. Add boundary tests for deterministic scripts and external inputs.
5. Run the complete local verification sequence.

```bash
mise run setup:default
mise run format:markdown
mise run lint:default
mise run test:default
MISE_ENV=development mise run test:template-smoke
```

`setup:default` installs the locked base and development toolchains, syncs the Python dependencies, and installs the
local hooks. CI uses only the public base toolchain; private `skillctl` and `orgctl` are development-only.

## Repository contract

```text
.
├── .claude-plugin/
│   └── plugin.json                 # generated by `apm pack --force`; identity, mirrored description, dependencies
├── apm.yml                         # APM package metadata, the source of the plugin manifest
├── skills/
│   └── template-agent-skill/
│       └── SKILL.md               # authoritative Agent Skill metadata and instructions
├── tools/
│   └── smoke_template.py           # full derived-repository smoke test
├── tests/                          # template contracts
├── mise-tasks/
│   ├── lint/skill                  # skillctl structural validation
│   ├── test/plugin-manifest        # plugin.json matches the APM-generated manifest
│   └── test/template-smoke         # orgctl initialization smoke test
├── template.init.toml              # orgctl identity replacement manifest
├── pyproject.toml                  # exact dependencies and inline Ruff configuration
└── uv.lock                         # resolved dependency graph
```

The plugin contains exactly one skill at `skills/<plugin-name>/SKILL.md`. The plugin name, skill directory, and
frontmatter name are identical. The plugin manifest contains `name`, `version`, `description`, and `author`, with
optional ordered marketplace `dependencies` objects with exactly `name` and `marketplace` fields; its
description exactly mirrors the skill frontmatter. APM metadata remains dependency-free. `skillctl` validates those
objects directly without changing the manifest.

## Validation scope

The released `skillctl` binary (`github:pretty-good-software-org/skillctl`, pinned in `.mise.development.toml`) enforces
the current Agent Skills name, description, root frontmatter, relative-link, and symlink boundaries plus this
organization's nested plugin contract, including optional marketplace dependencies. `mise run lint:development` runs
the default linters plus `lint:skill`, which invokes `skillctl validate claude-plugin .` from the development profile.
`skillctl` is maintained in its own repository because the official `skills-ref` repository describes its reference
library as demonstrational rather than production software. This is separate from
`platform-skill-create/scripts/validate_skill.py`, which is unrelated product runtime behavior owned by a different
repository, not this template.

Validation stays repository-only and does not ship with generated plugins. It does not measure whether the skill
improves model behavior. Use a separate evaluation harness for paired runs, trigger precision and recall, regression
campaigns, and human review.

## Tool ownership

- Mise pins Python, uv, and repository-wide command-line tools in the base profile, while the development profile pins
  the released `skillctl` v2.1.0 binary so `mise run lint:development` can validate the complete plugin manifest.
- The development profile pins the private `orgctl` release to v0.12.2, which runs `orgctl repo init` with the `remove`
  manifest mechanism in the explicit template smoke test and provides `orgctl merge --expected-head`; CI does not need
  cross-repository credentials. Its releases carry no GitHub artifact attestations, so the locked checksums are its
  provenance control.
- `UV_NO_MANAGED_PYTHON=1` forces uv to use the exact Mise Python runtime.
- `pyproject.toml` and `uv.lock` own Python dependencies. Every `uv run` in the Mise tasks and Lefthook hooks passes
  `--locked`, so a `uv.lock` that no longer matches `pyproject.toml` fails them instead of being re-locked silently;
  run `uv lock` after editing dependencies. Dependabot uses the `uv` ecosystem so its updates refresh `uv.lock`.
- The shared `ci-shared` `setup/mise` action mints a repository-scoped installation token restricted to the declared
  public tooling; private skill validation is installed only in the development profile and is not required by CI.
- Ruff owns Python linting and formatting.
- rumdl owns Markdown formatting and linting.
- pytest owns deterministic tooling tests.
- The explicit smoke task runs `orgctl repo init` and verifies an initialized repository through setup, formatting,
  lint, and tests. The default test task excludes this template-only check so initialized repositories and CI do not
  require the private organization CLI.
- `template.init.toml`'s top-level `remove` list deletes `tools/smoke_template.py`,
  `tests/test_smoke_template.py`, and `mise-tasks/test/template-smoke` during `orgctl repo init`; derived repositories
  do not retain any of those three paths. Structural validation runs through the
  Mise-pinned `skillctl` binary in both this template and every derived repository, not a copied script.
- OpenTofu in `org-github-infrastructure` owns repository settings and rulesets.

## Supported platforms

The toolchain is POSIX-only and supports Linux ARM64, Linux x64 including glibc and musl, and macOS ARM64 and x64.
Windows is not supported. The canonical lock files intentionally omit Windows artifacts; refresh the supported
platforms explicitly:

```bash
mise lock --platform linux-arm64,linux-arm64-musl,linux-x64,linux-x64-musl,macos-arm64,macos-x64
MISE_ENV=development mise lock \
  --platform linux-arm64,linux-arm64-musl,linux-x64,linux-x64-musl,macos-arm64,macos-x64
```
